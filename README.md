# PostgreSQL natural-language assistant

This solution contains two workflows:

- `workflows/postgresql-assistant.json` turns a question into a parameterized SQL plan, validates it, runs it with PostgreSQL, and returns rows plus presentation-ready representations.
- `workflows/render-output.json` converts the result to text, XLSX, RTF (Word-compatible), HTML, a PNG chart, or PDF. Rendering is separate so retries never rerun SQL.

## Safety model

The SQL validator accepts one `SELECT` or `WITH` statement, blocks comments, stacked statements, DML, DDL, locking clauses, administrative commands, and sensitive PostgreSQL file/network functions. It checks schema/table allowlists and forces a bounded `LIMIT`.

That validator is defense in depth, not the primary boundary. Production must use a dedicated database login that inherits only the `analytics_reader` role shown in `schema.sql`, has no `CREATE` or `TEMP` privilege, and has a short `statement_timeout`. Point the assistant at a replica or curated reporting schema when possible.

## Request contract

```json
{
  "test_mode": false,
  "request_id": "client-generated-id",
  "question": "Show monthly completed revenue for 2026 as a bar chart.",
  "llm_provider": "openai",
  "output_format": "chart",
  "guardrails": {
    "allowed_schemas": ["analytics"],
    "allowed_tables": ["orders"],
    "max_rows": 100
  }
}
```

Supported output formats are `json`, `text`, `chart`, `xlsx`, `rtf`, `html`, and `pdf`. The assistant workflow always returns JSON with `rows`, `text`, `html`, and `chart_config` where applicable. Send that receipt to the renderer only when a binary file is required.

## Credential-free tests

Allowed chart query:

```powershell
$body = Get-Content -Raw .\4-postgresql-chatbot\fixtures\revenue-chart.json
Invoke-RestMethod -Method Post -Uri '<SQL_ASSISTANT_TEST_WEBHOOK_URL>' -ContentType 'application/json' -Body $body
```

Expected: three rows, SQL ending in `LIMIT 100`, and a Chart.js-compatible bar configuration.

Blocked mutation:

```powershell
$body = Get-Content -Raw .\4-postgresql-chatbot\fixtures\blocked-delete.json
Invoke-RestMethod -Method Post -Uri '<SQL_ASSISTANT_TEST_WEBHOOK_URL>' -ContentType 'application/json' -Body $body
```

Expected: `allowed: false`; no database node runs.

## Renderer behavior

- `text`: UTF-8 `.txt` generated by n8n Convert to File.
- `xlsx`: native XLSX generated by Convert to File.
- `rtf`: Word-compatible rich-text document generated locally. Replace this branch with Microsoft Graph or a document service if true `.docx` is mandatory.
- `html`: standalone HTML report.
- `chart`: Chart.js configuration; production calls QuickChart for PNG.
- `pdf`: production posts generated HTML to Gotenberg.
- In `test_mode`, external chart/PDF services are bypassed and the render plan is returned as JSON.

## Production controls

- Authenticate and rate-limit the webhook.
- Derive allowlists server-side. Do not accept them from an untrusted caller as the production authority.
- Exclude personal, secret, payment, and row-level-security-protected columns from schema context.
- Consider `EXPLAIN (FORMAT JSON)` plus a cost threshold before executing generated SQL.
- Log the question, approved SQL hash, duration, row count, and rejection reason, but not full sensitive results.
- Add human approval for high-cost analytical queries or exports above a policy threshold.
